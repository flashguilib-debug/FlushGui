FlashGui 0.1.6

App desktop Python in 3 righe. Componenti pronti, finestra personalizzabile, API uniforme.

FlashGui è una libreria Python che ti offre calcolatrice, blocco note, paint, orologio, calendario, ricerca file già funzionanti con una riga di codice, più un componente WINDOW ad alto livello per costruire qualsiasi interfaccia usando coordinate proporzionali (0.0 → 1.0) e font che si ridimensionano automaticamente. Ogni modulo supporta temi light e dark, personalizzazione completa via Edit(), logica iniettabile via Logic() e un set di API comuni (timer, clipboard, HTTP asincrono).

Installazione

$ pip install FlashGui
Richiede Python 3.9+ e wxPython 4.2+. Installa anche charset-normalizer (usato da NOTEPAD e WINDOW per aprire file con encoding automatico).

  • WINDOW — aggiunto add_combobox, add_spinctrl, add_separator, add_image, add_menu, dialogs (ShowInputDialog, ShowYesNoDialog, OpenFolderDialog), file helpers (LoadTextFromFile, SaveTextToFile), BindKey, gestione finestra (SetTitle, Minimize, Maximize, Restore, SetOpacity, SetIcon), SetCloseHandler, exit().

CALCULATOR
Calcolatrice completa con display, griglia numerica e operatori, tema chiaro/scuro, ogni pulsante personalizzabile.
from FlashGui import CALCULATOR

calc = CALCULATOR(
    title="Calculator",
    size=(3, 2),

📘 Esempio

from FlashGui import CALCULATOR

calc = CALCULATOR(title="Calcolatrice personalizzata", style="dark")
calc.Edit(button_eq_bg=(0,200,100), button_eq_fg=(0,0,0), message_error="Errore!")

def on_equal():
    result = calc.Evaluate()
    calc.CopyToClipboard(result)  # copia il risultato negli appunti

calc.Logic(button_eq_command=on_equal)
calc.run()

SEARCHER NEW in 0.1.6
Ricerca file e cartelle in modo ricorsivo o flat, con filtri per tipo, query sul nome e stato in tempo reale. Thread-safe, annullabile in qualsiasi momento.
from FlashGui import SEARCHER

searcher = SEARCHER(title="Ricerca File", size=(3,2), style="light")
searcher.run()

Funzionamento di default

Cliccando Search viene avviato un thread in background che scansiona la directory indicata (o tutte le unità disco su Windows se vuota). I risultati appaiono in una ListCtrl con colonne Name, Type, Folder, Size, Modified. Il pulsante Stop interrompe la ricerca in modo sicuro. Clear svuota i risultati. Browse apre un dialog per scegliere la directory.

📘 Esempio

from FlashGui import SEARCHER

s = SEARCHER(title="Cerca file Python", style="dark")
s.Edit(title_text="🔍 Ricerca File", btn_search_text="Cerca", btn_cancel_text="Stop")

s.SetSearchType("Files")
s.SetRecursive(True)

    s.SetStatus(f"Trovati {count} file Python!")

def on_open(path):
    import subprocess
    subprocess.Popen(["code", path])  # apri in VS Code

s.Logic(finish_command=on_finish, open_command=on_open)
s.run()

WINDOW
Tela bianca proporzionale: aggiungi qualsiasi widget con coordinate relative 0.0→1.0. Font, layout e resize sono automatici.
from FlashGui import WINDOW

win = WINDOW(
    title="La mia app",
    size=(800, 600),      # pixel assoluti (largh, alt)
    style="light",         # "light" o "dark"
    color=(240, 240, 240),
    icon=None,
    maximized=False,
    min_size=(400, 300),  # pixel o float 0→1
    max_size=(1920, 1080)
)
Tutte le coordinate relx, rely sono il centro del widget (0.0 = bordo sinistro/superiore, 1.0 = bordo destro/inferiore). relw, relh sono larghezza e altezza proporzionali al pannello.

Tutti i metodi add_* accettano i parametri comuni: relx, rely, relw, relh, fg, bg, font_scale, bold, tooltip, visible (dove applicabile). Restituiscono un FGProxy che puoi passare a Modify().

Metodo Modify(widget, **kwargs)

Aggiorna uno o più attributi di un widget già creato senza doverlo ricreare. Accetta widget= (il proxy restituito da add_*) oppure index= (posizione 0-based nella lista widget).

# Creo un label e poi lo modifico
lbl = win.add_label(text="Hello", relx=0.5, rely=0.3)
win.Modify(lbl, text="World", fg=(255,0,0), bold=True)

API Comuni a tutti i moduli AGGIORNATO

Le API seguenti sono disponibili su tutti i moduli: CALCULATOR, NOTEPAD, PAINT, CLOCK, CALENDAR, SEARCHER, WINDOW.

Timer

AddTimer(delay_ms, func, name=None) → wx.Timer
Avvia un timer one-shot: chiama func() una sola volta dopo delay_ms millisecondi. Se fornito, name permette di identificare il timer per cancellarlo con DelTimer. Restituisce il timer.
AddRepeatTimer(interval_ms, func, name=None) → wx.Timer
Avvia un timer ripetitivo: chiama func() ogni interval_ms millisecondi finché non viene fermato con DelTimer.
DelTimer(timer_or_name)
Ferma e rimuove un timer. Accetta il nome stringa (se fornito in fase di creazione) oppure il riferimento all'oggetto timer.
# Esempio: aggiorno un label ogni secondo
import time
lbl = win.add_label(relx=0.5, rely=0.5)

win.AddRepeatTimer(1000, lambda: lbl.SetText(time.strftime("%H:%M:%S")), name="clock")

# Per fermarlo dopo 10 secondi:
win.AddTimer(10000, lambda: win.DelTimer("clock"))

Clipboard

CopyToClipboard(text)
Copia text negli appunti di sistema. In CALCULATOR e NOTEPAD il parametro è opzionale: se omesso copia il valore del display / la selezione.
GetClipboardText() → str
Restituisce il testo attualmente negli appunti di sistema. Restituisce stringa vuota se non è disponibile testo.

HTTP asincrono

Ogni modulo include un metodo per inviare richieste HTTP in un thread di background, senza bloccare la UI.

SendRequest(url, method="GET", data=None, headers=None, callback=None, use_json=False)
Invia una richiesta HTTP in background.
• method: "GET", "POST", "PUT", "DELETE", ecc.
• data: dizionario dei dati da inviare nel body.
• headers: dizionario di header aggiuntivi.
• use_json: se True, serializza data come JSON e imposta Content-Type: application/json.
• callback(response_text, error_or_None): funzione chiamata sul thread principale al completamento. 
# Esempio: chiamata API REST da WINDOW
def on_response(resp, err):
    if err:
        win.ShowMessageBox(f"Errore: {err}")
    else:
        lbl.SetText(resp)

win.SendRequest(
    url="https://api.example.com/data",
    method="POST",
    data={"key": "valore"},
    use_json=True,
    callback=on_response
)

Filosofia: Logic() vs Edit()

Edit() gestisce l'aspetto visivo: colori, testi, etichette.
Logic() gestisce il comportamento: quali funzioni vengono chiamate agli eventi.

Questa separazione netta permette di:

  • Tradurre completamente l'interfaccia chiamando solo Edit() con le stringhe localizzate.
  • Iniettare la logica applicativa senza toccare la UI, mantenendo il codice pulito.
  • Ridefinire solo i comportamenti che interessano: se non passi un parametro a Logic(), il comportamento default rimane attivo.
